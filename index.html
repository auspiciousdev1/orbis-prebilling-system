ORBIS

Order & Revenue Billing Information System

A dummy SAP/Oracle-style system holding everything an invoice is built from — contracts, customer purchase orders, sales orders, deliveries and source documents — plus the pre-invoice billing drafts a validation tool is meant to check. Static JSON API, real PDFs, hostable on GitHub Pages.

Transactional system

ORBIS ERP

Billing drafts, sales orders with lines and holds, contracts with price lists and clauses, customer POs, deliveries, customer and item master, tax rules, document repository.

 Analytics

ORBIS Insight

Qlik-style sheet: selections at the top govern KPI tiles, order value by customer and week, draft value by tax treatment, and the billing draft list.

Join keys

draft.sales_order = sales_order.order_number order.customer_po_number = purchase_order.po_number order.contract_number = contract.contract_number order.delivery_number = delivery.delivery_number draft.lines.item_number + contract → price_list.contract_price draft.tax_code = tax_rule.tax_code

Billing draft in three shapes

EndpointShapeUse for
api/billing-drafts.jsonOne row per draft, ~50 header fieldsWorklists, header checks
api/billing-drafts/{draft_number}.jsonHeader + nested lines + totalsWorking a single draft
api/billing-draft-lines.jsonOne row per line, 93 columns, header denormalisedField-by-field validation, CSV

On the flat endpoint, columns prefixed ref_ are joined from the contract, purchase order, sales order, delivery and tax rules — the values the draft should agree with.

One call per draft

api/validation-packages/{draft_number}.json returns a billing draft with every upstream object already joined — sales order, purchase order, contract and price list, delivery, customer, tax rules, item master, and the URLs of all four source PDFs. One request instead of six. The whole model is also available in a single api/bundle.json, and the API describes itself at api/openapi.json.

Connecting a validation tool

import requests

BASE = "https://<your-user>.github.io/<your-repo>"
pkg = requests.get(f"{BASE}/api/validation-packages/BD-2026-5501.json").json()

draft, order  = pkg["billing_draft"], pkg["sales_order"]
contract      = pkg["contract"]
prices  = {p["item_number"]: p["contract_price"] for p in contract["price_list_lines"]}
shipped = {l["item_number"]: l["shipped_quantity"] for l in pkg["delivery"]["lines"]}

for line in draft["lines"]:
    if line["line_type"] != "GOODS":
        continue
    expected = prices.get(line["item_number"])
    if expected is not None and abs(line["unit_price"] - expected) > 0.01:
        print(line["item_number"], "price", line["unit_price"], "expected", expected)
    if line["quantity_to_bill"] > shipped.get(line["item_number"], 0):
        print(line["item_number"], "billing more than shipped")

# source documents, e.g. the signed contract PDF
pdf = requests.get(f"{BASE}/{pkg['documents'][0]['url']}").content

api/field-map.json lists all 24 invoice fields with the authoritative source and precedence for each, and api/mismatches.json is the answer key — 14 defects were deliberately seeded into the drafts so a validation run can be scored on recall and precision.
